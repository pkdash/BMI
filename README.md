# BMI Model Wrappers Monorepo

This repository contains Python BMI wrapper projects for hydrological models (C/C++/Fortran).

## Purpose

This monorepo is used to:

- Build and maintain Python-accessible BMI wrappers for multiple models
- Keep each model implementation isolated while following shared conventions
- Standardize regeneration, build, test, and packaging workflows
- Make onboarding easier for future model wrappers

## Model Project Conventions

Each model folder should include:

- A model-specific `README.md`
- A model-specific `babel.toml`
- A generated/maintained Python package (`pymt_<model>`)
- Helper scripts for regenerate/build/test (as needed)

## Shared BMI Value Exchange (`common/`)

The Cython `.pyx` file of every wrapper is generated from one template per
language family (C, C++, Fortran) in `common/templates/`, so `get_value`,
`get_value_ptr`, `set_value` and `*_at_indices` behave identically for all
models:

- dtype and element count come from the native `get_var_type`,
  `get_var_itemsize` and `get_var_nbytes` (never from the grid size);
- buffers are validated (dtype, size, contiguity) before reaching native code,
  and `set_value` accepts arrays, lists and scalars with safe casting;
- `get_value_ptr` returns a NumPy view that keeps the model object alive.

After changing anything in `common/`, re-render and commit the results:

```sh
python common/render_wrappers.py          # writes <MODEL>/wrapper/ and pymt_<model>/.../lib/
python common/render_wrappers.py --check  # CI-style check that nothing is stale
```

Details, design notes and the test instructions are in
[`common/README.md`](common/README.md).

## Setting up and parameterizing models (`bmi_setup/`)

`bmi_setup` is a small pure-Python package on top of the wrappers:

- `open_model` guarantees `finalize` and handles the working directory;
- `Model.set` broadcasts scalars to every layer, with length checks;
- `catalogs/<model>.json` records, for CFE, Noah-OWP, PET and TOPMODEL, each
  parameter's config key and whether setting it through BMI after `initialize`
  is proven identical to a config edit;
- the config codecs edit a model's own config file in place.

See [`bmi_setup/README.md`](bmi_setup/README.md).

## Contribution / Workflow

1. Create a model folder at repo root (example: `PET/`).
2. Add model-specific `babel.toml` and package naming (`pymt_<model>`).
3. Regenerate wrapper code with Babelizer.
4. Apply local patches (if required for packaging/runtime). `post_babelize_patch.sh`
   installs the generated wrapper from `<MODEL>/wrapper/`; register a new model in
   `common/render_wrappers.py` (`MODELS`) and run it to create that directory.
5. Build and test in a clean environment (or Docker).
6. Commit only source/config/docs (not build artifacts).

## Git Hygiene

- Track source code, configuration, and docs.
- Do **not** track generated artifacts (`build/`, `dist/`, `*.egg-info`, `__pycache__`, compiled binaries).
- Keep one git repository at `BMI/` root (no nested `.git` repositories).
